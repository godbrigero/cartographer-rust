# Porting guide (conventions for every module)

The C++ source of truth is `../cartographer/` (read-only). Architecture reports
for each area are in `docs/architecture/`.

## Layout

* Workspace crates:
  * `crates/ceres` (package `cartographer-ceres`, lib name `ceres`): focused
    pure-Rust port of the Ceres Solver subset Cartographer uses (Jets/autodiff,
    `rotation.h`, `cubic_interpolation.h`, loss functions, local
    parameterizations, `Problem`, trust-region LM `Solve`).
  * `crates/cartographer`: the faithful port. One Rust file per C++ `.h`/`.cc`
    pair, at the same relative path, with `2d` -> `two_d` and `3d` -> `three_d`
    in *directory* names (file names keep `_2d`/`_3d` suffixes).
    Example: `mapping/internal/2d/scan_matching/ceres_scan_matcher_2d.{h,cc}`
    -> `src/mapping/internal/two_d/scan_matching/ceres_scan_matcher_2d.rs`.
* The skeleton (all `mod.rs` files and one empty file per C++ unit) already
  exists. Fill in the files of your scope; do not reshuffle modules owned by
  other people. If you need a new file (e.g. a shared helper), add it next to
  the closest C++ counterpart and say so in your report.
* C++ namespaces that do not match directories (`mapping::scan_matching`,
  `mapping::optimization`, `mapping::constraints`) have re-export modules
  (`src/mapping/scan_matching.rs` etc.). Add `pub use` lines there for the
  types you port so `cartographer::mapping::scan_matching::CeresScanMatcher2D`
  works like in C++. Likewise, public types in `mapping/two_d/*` or
  `mapping/internal/*` that are in the C++ `cartographer::mapping` namespace
  should be re-exported from `mapping/mod.rs` *by whoever owns that file at the
  end* (just list them in your report).
* Protos: generated by `build.rs` (protox + prost). Use them via
  `crate::mapping::proto::Submap`, `crate::transform::proto::Rigid3d`,
  `crate::mapping::scan_matching::proto::CeresScanMatcherOptions2D`, etc.
  Never edit files in `crates/cartographer/proto/` (they must stay
  byte-identical to the C++ ones). prost maps `type` -> `r#type`, message
  fields -> `Option<T>`, repeated -> `Vec<T>`, enums -> `i32` fields with
  `try_from`/setter helpers.

## Naming

* Types keep their C++ names (`ProbabilityGrid`, `Rigid3d`, `MapBuilder`,
  `CeresScanMatcher2D`). Methods/functions become snake_case
  (`AddTrajectoryBuilder` -> `add_trajectory_builder`,
  `GetDictionary` -> `get_dictionary`). Constants keep C++ names in
  SCREAMING_CASE (`kUnknownProbabilityValue` -> `UNKNOWN_PROBABILITY_VALUE`).
* C++ templates over float/double (`Rigid3<T>`) become generics over
  `nalgebra::RealField + Copy` so they also work with `ceres::Jet<N>`.
* Free functions `ToProto`/`FromProto` -> `to_proto`/`from_proto` (free
  functions in the same module, as in C++).
* `Create*Options(LuaParameterDictionary*)` -> `create_*_options(&LuaParameterDictionary) -> proto::...`.

## Semantics

* Keep algorithms, constants, default parameters and numerical order of
  operations. float vs double must match the C++ (`Eigen::Vector3f` ->
  `nalgebra::Vector3<f32>`). Integer division/rounding: `std::lround` ->
  `common::math::round_to_int`-style helpers (round half away from zero, as
  `f64::round`), `std::floor` -> `.floor()`.
* Eigen -> nalgebra: `Eigen::Vector3d` -> `Vector3<f64>`,
  `Eigen::Quaterniond` -> `UnitQuaternion<f64>` (beware: Eigen stores
  `(x,y,z,w)` and constructs `Quaterniond(w,x,y,z)`; nalgebra
  `Quaternion::new(w,i,j,k)`; protos store `x,y,z,w`). `Eigen::AngleAxisd`
  -> `UnitQuaternion::from_axis_angle` / `from_scaled_axis`.
* `CHECK(...)`/`CHECK_EQ` -> `assert!`/`assert_eq!` with an equivalent
  message; `LOG(FATAL)` -> `panic!`; `LOG(INFO|WARNING|ERROR)` -> `log::info!`
  etc. `DCHECK` -> `debug_assert!`.
* Ownership: `std::unique_ptr<T>` -> `Box<T>`/plain value;
  `std::shared_ptr<const T>` -> `Arc<T>`; `absl::Mutex` + `GUARDED_BY` ->
  `std::sync::Mutex<Inner>`; callbacks -> `Box<dyn Fn(..) + Send + Sync>`.
  Where Rust ownership forces a structural change, keep the public API shape
  and document the change in a `//` comment starting with `// RUST PORT NOTE:`.
* Virtual interfaces (`PoseGraphInterface`, `TrajectoryBuilderInterface`,
  `PointsProcessor`, `Submap2D` vs `Submap3D` via `Submap`) -> traits
  (object-safe where C++ uses them polymorphically).
* No `unsafe`. No `todo!()`/`unimplemented!()` in shipped code paths.
* Numbers in docs/comments copied from C++ comments are fine; keep the C++
  explanatory comments (translated) where they explain algorithms.

## Tests

* Port **every** test of every `*_test.cc` in your scope into a
  `#[cfg(test)] mod tests` at the bottom of the corresponding Rust file
  (or into `crates/cartographer/tests/` if it needs only public API).
  Naming: `TEST(RigidTransformTest, ToProto)` -> `fn rigid_transform_test_to_proto()`
  is NOT required; use a submodule per C++ test suite:
  `mod rigid_transform_test { #[test] fn to_proto() {...} }`.
* Keep inputs, iteration counts and tolerances. `EXPECT_NEAR(a, b, eps)` ->
  `assert!((a - b).abs() <= eps, ...)` or `approx::assert_abs_diff_eq!`.
  Do not weaken tolerances; if one must change, document why next to it.
* gmock-based tests: write small hand-rolled fakes (no `mockall` unless
  unavoidable).
* Where coverage is thin, add property tests (`proptest`) for math/transform
  code and round-trip tests for proto conversions.
* Randomized C++ tests use `std::mt19937` with fixed seeds; use a seeded
  `rand::rngs::StdRng`/`SmallRng` (exact value equality with C++ random
  streams is not required unless the test asserts exact values).

## Quality bar

* `cargo build`, `cargo test -p cartographer`, `cargo clippy --all-targets -- -D warnings`
  and `cargo fmt` must be clean for your files before you finish.
* Public items get a short doc comment (C++ header comments are a good source).
* Report back: files ported, tests ported (C++ name -> Rust name), anything
  not ported and why, any RUST PORT NOTEs, re-exports you want added.

## Already-ported APIs (cheat sheet)

* `common::time`: `Time`, `Duration` (100 ns ticks, i64); `from_seconds`,
  `to_seconds`, `from_milliseconds`, `from_universal`, `to_universal`;
  `Time::min()/max()`.
* `common::port`: `round_to_int`, `round_to_int64`, `fast_gzip_string`,
  `fast_gunzip_string`. `common::math`: `clamp`, `power`, `pow2`,
  `deg_to_rad`, `rad_to_deg`, `normalize_angle_difference`, `atan2(&Vector2)`.
* `common::lua_parameter_dictionary::LuaParameterDictionary` (`get_double`,
  `get_int`, `get_bool`, `get_string`, `get_dictionary`, `get_non_negative_int`,
  `get_array_values_as_*`, `has_key`); tests use
  `common::internal::testing::lua_parameter_dictionary_test_helpers::make_dictionary(code)`.
  Every key must be read exactly once (checked on drop), like C++.
* `common::thread_pool::{ThreadPool, ThreadPoolInterface}`, `common::task::Task`
  (`Arc<Task>`), `common::internal::testing::ThreadPoolForTesting`.
* `common::internal::ceres_solver_options::{create_ceres_solver_options_proto, create_ceres_solver_options}`.
* `transform::rigid_transform::{Rigid2, Rigid3, Rigid2d, Rigid2f, Rigid3d, Rigid3f}`
  (generic over `RealField + Copy`; `Rigid3::rotation()` returns
  `&nalgebra::Quaternion<T>`), `transform::transform::{get_angle, get_yaw,
  rotation_quaternion_to_angle_axis_vector, angle_axis_vector_to_rotation_quaternion,
  project_2d, embed_3d, to_rigid2, to_rigid3, to_proto, to_eigen}`,
  `transform::timestamped_transform`, `transform::transform_interpolation_buffer`,
  test helpers `transform::rigid_transform_test_helpers::{IsNearly, assert_is_nearly}`.
* `ceres` crate (see `crates/ceres/src/lib.rs` docs and `crates/ceres/DESIGN.md`):
  `Jet<N>`, `Scalar` (`RealField + Copy`, `T::constant(f64)`, `x.scalar_part()`),
  `CostFunctor` (`fn evaluate<T: Scalar>(&self, params: &[&[T]], residuals: &mut [T]) -> bool`),
  `AutoDiffCostFunction::<F, N>::new(functor, num_residuals, &[block sizes])`,
  `CostFunction`, `SizedCostFunction`, loss functions, local parameterizations
  (`QuaternionParameterization`, `AutoDiffLocalParameterization`, `SubsetParameterization`),
  `Problem` (handle-based: `add_parameter_block(&[f64]) -> ParameterBlockId`,
  `add_residual_block(..)`, `parameter_block(id)`), `solve(&SolverOptions, &mut Problem, &mut SolverSummary)`,
  `ceres::rotation::*`, `ceres::cubic_interpolation::{Grid2, BiCubicInterpolator, ..}`.
* Simulator for tests: `crates/sim` (`cartographer-sim`), dev-dependency only.
